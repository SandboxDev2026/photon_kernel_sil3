# Photon Kernel Sandbox - 隔离网关服务

独立可运行的边界代理网关（网络三层防御中的第二层）。

所有沙盒流量强制经过此网关，沙盒本身没有直接路由。

## 功能

| 功能 | 实现 | 状态 |
|------|------|------|
| TCP 透明代理 | 实际转发沙盒流量到目标地址 | ✅ 可运行 |
| 域名/IP白黑名单 | 实际 DNS 解析 + 域名匹配（支持通配符 `*.example.com`） | ✅ |
| 连接数限流 | 实际跟踪每沙盒并发连接数，超额拒绝 | ✅ Token Bucket |
| 带宽限流 | token bucket 算法，实际限制单流/总带宽 | ✅ |
| DNS 代理/劫持 | 内置 DNS 服务器，只转发到授权 DNS，阻止自定义 DNS | ✅ 可运行 |
| 内网隔离兜底 | 再次校验 RFC1918 + 云元数据地址 | ✅ |
| 审计日志 | 每条连接记录租户ID、CapabilityToken、HMAC 哈希链 | ✅ |

## 快速开始

```bash
# 启动网关（需要 root 绑定 53 端口）
sudo python3 server/gateway/isolation_gateway.py \
  --listen 0.0.0.0:8080 \
  --dns-listen 0.0.0.0:53 \
  --dns-server 8.8.8.8 \
  --dns-server 1.1.1.1 \
  --max-conns 64 \
  --max-rate 10 \
  --max-bandwidth 100 \
  --verbose
```

## 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--listen` | `0.0.0.0:8080` | TCP 代理监听地址 |
| `--dns-listen` | `0.0.0.0:53` | DNS 代理监听地址 |
| `--dns-server` | `8.8.8.8, 1.1.1.1` | 授权 DNS 服务器（可重复） |
| `--max-conns` | `64` | 每沙盒最大并发连接数 |
| `--max-rate` | `10` | 每秒最大新建连接数 |
| `--max-bandwidth` | `100` | 总带宽限制（Mbps，0=不限制） |
| `--no-internal-block` | - | 禁用内网 IP 拦截 |
| `--no-dns-hijack` | - | 禁用 DNS 劫持 |
| `--audit-log` | `/var/log/photon/gateway_audit.log` | 审计日志文件 |
| `--verbose` | - | 详细日志 |

## DNS 劫持原理

```
沙盒内 /etc/resolv.conf → nameserver 10.0.99.1 (网关)
         │
         ▼
网关 DNS 代理 (UDP:53)
         │
         ├─ 检查域名黑名单 → 拒绝
         │
         └─ 转发到授权 DNS (8.8.8.8 / 1.1.1.1)
              │
              └─ 轮询，超时切换

沙盒无法使用自定义 DNS（8.8.4.4 等）绕过域名白名单，
因为所有 53 端口流量都被 iptables DNAT 到网关 DNS 代理。
```

## 限流算法

### 连接数限流 (ConnectionTracker)
- 每沙盒最大并发连接数：`--max-conns`
- 每秒最大新建连接数：`--max-rate`
- 超额直接拒绝（TCP RST）

### 带宽限流 (TokenBucket)
- 令牌桶算法：`rate = max_bandwidth_mbps * 1024 * 1024 / 8` bytes/sec
- 突发容量：2 秒令牌
- 令牌不足时等待（超时 0.5s），超时则丢弃

## 与 eBPF 内网隔离的关系

网关是第二层防御，eBPF 是第三层（沙盒实例级）：

| 层 | 位置 | 拦截点 | 优势 |
|----|------|--------|------|
| 网关 | 网络边界 | TCP 代理 + DNS 代理 | 域名级控制、集中审计、限流 |
| eBPF | 沙盒进程内 | cgroup/connect4 + XDP | 内核态、零绕过、兜底 |

即使网关配置错误或被绕过，eBPF 在内核态继续拦截内网 IP。

## 生产部署建议

1. **高可用**：部署多个网关实例，沙盒默认网关指向 VIP
2. **性能**：带宽限流会增加延迟，高吞吐场景可适当调大 `--max-bandwidth`
3. **安全**：网关运行在独立主机/容器，不与沙盒共享网络命名空间
4. **监控**：审计日志接入 ELK/Splunk，告警异常连接模式
