## 一、新增模块说明

### 1.1 M2 检测网关（语义动量过滤模块）

**文件**: `evolution/m2_gateway.py`（约 600 行）

**核心思想**：在沙盒入口处叠加语义动量过滤，补上认知层空白。

**与现有安全层的关系**：
- 规则层（seccomp/Landlock）：系统调用和文件访问的静态规则
- **认知层（M2 Gateway）**：语义层面的风险认知和动量过滤 ★新增
- 运行时层（RuntimeGuard）：执行前二次校验和资源限制
- 审计层（HMAC 审计链）：所有操作的不可篡改记录

**核心能力**：

| 能力 | 说明 |
|------|------|
| 语义特征提取 | 从代码中提取 11 种语义特征（危险API、系统调用、文件操作、网络操作、进程操作、代码执行、混淆、提权、数据外泄、沙盒逃逸） |
| 风险分数计算 | 基于特征严重程度和置信度加权计算（0.0-1.0） |
| 语义动量计算 | 计算风险变化率、异常分数、高风险特征占比 |
| 混淆检测 | 检测十六进制编码、Unicode编码、Base64解码、chr()拼接等混淆手段 |
| 过滤决策 | 4 级决策：ALLOW / WARN / REJECT / QUARANTINE |
| 审计记录 | 所有过滤决策记录审计日志，支持事后追溯 |
| 统计信息 | 请求数、允许率、拒绝率、审计日志大小等 |

**危险模式覆盖**（28 种正则模式）：
- 代码执行：eval/exec/compile
- 系统命令：os.system/os.popen/subprocess
- 文件操作：/etc、/proc、/sys、/dev 路径访问，os.remove，shutil.rmtree
- 网络操作：socket，requests，urllib
- 进程操作：os.fork，os.execv，multiprocessing
- 提权尝试：os.setuid，os.setgid，sudo
- 数据外泄：base64.b64encode，/dev/tcp
- 沙盒逃逸：ptrace，nsenter，mount --bind，chroot

**决策阈值**：
- 风险分数 < 0.3：ALLOW（允许）
- 0.3 ≤ 风险分数 < 0.6：WARN（警告但允许，记录审计）
- 0.6 ≤ 风险分数 < 0.85：REJECT（拒绝）
- ≥ 0.85 或检测到严重特征：QUARANTINE（隔离，需人工审批）

**特殊规则**：
- 检测到沙盒逃逸尝试 → 直接 REJECT
- 检测到提权尝试（CRITICAL）→ 直接 QUARANTINE
- 检测到代码混淆 → 增加异常分数，提升风险等级

### 1.2 SIL-3 声明修正

**文件**: `docs/threat_model.md`

**修正前**: "不影响 SIL-3 标准路径合规判定"
**修正后**: "不影响 SIL-3 合规引擎（设计目标）的路径合规判定"

**修正原因**: 避免合规声明与验证状态不符。SIL-3 是 IEC 61508 功能安全完整性等级，本项目中的"SIL-3 合规引擎"是概念借用（AI 法案合规引擎），并非 IEC 61508 认证。明确标注为"设计目标"，避免误导。

### 1.3 业务影响面度量规范

**文件**: `docs/business_impact_metrics.md`（约 300 行）

**规范依据**: 第十三条（业务影响面控制）

**核心要求**: 单个沙盒实例故障/逃逸/资源耗尽时，业务影响面 ≤ 5%。

**LightPool 度量指标**：

| 指标 | 起步上限 | 计算方式 |
|------|---------|---------|
| 单实例并发上限 | ≤ 5% 集群总并发 | 单实例并发 / 集群总并发 × 100% |
| 单实例内存上限 | ≤ 5% 节点内存 | 单实例内存 / 节点总内存 × 100% |
| 单实例 CPU 上限 | ≤ 5% 节点 CPU | 单实例CPU / 节点总CPU × 100% |
| 故障爆炸半径 | ≤ 5% 总 QPS | 受影响QPS / 集群总QPS × 100% |

**StrongPool 度量指标**：

| 指标 | 起步上限 | 计算方式 |
|------|---------|---------|
| 单 VM 并发上限 | ≤ 5% 集群总并发 | 单VM并发 / 集群总并发 × 100% |
| 单 VM 内存上限 | ≤ 5% 节点内存 | 单VM内存 / 节点总内存 × 100% |
| 单 VM CPU 上限 | ≤ 5% 节点 CPU | 单VM CPU / 节点总CPU × 100% |
| VM 逃逸影响面 | ≤ 5% 集群资源 | 可访问资源 / 集群总资源 × 100% |
| 快照克隆影响面 | ≤ 5% 总 VM 数 | 受影响VM数 / 总VM数 × 100% |

**集群级要求**：
- 跨可用区部署（≥ 2 AZ）
- 单可用区流量占比 ≤ 50%
- 单节点故障影响 ≤ 5%
- HPA 最小副本 ≥ 3

**监控告警**：
- `sandbox_instance_failure_impact_ratio` > 5% → CRITICAL 告警
- `sandbox_vm_escape_attempts` > 0 → CRITICAL 告警
- `sandbox_resource_exhaustion_events` > 0/min → 告警

## 七、剩余风险与建议

### 高优先级建议（P1）
1. **启动第三方安全审计**：选择具备资质的审计机构，完成静态代码审计、动态渗透测试、模糊测试
2. **升级依赖版本**：OpenSSL >=3.0.7、grpcio >=1.62.0、Firecracker >=1.5.0
3. **M2 网关规则优化**：当前基于正则匹配，生产环境可集成 AST 分析提升准确率
4. **业务影响面验证**：在生产环境进行故障演练，验证实际影响面 ≤5%

### 中优先级建议（P2）
1. **M2 网关持久化**：当前审计日志仅内存存储，生产环境需持久化
2. **M2 网关规则热更新**：支持运行时更新危险模式库，无需重启
3. **M2 网关多语言支持**：当前主要针对 Python，需扩展 JavaScript/Shell/Go 等
4. **混淆检测增强**：集成 AST 级别的混淆检测，提升准确率

### 低优先级建议（P3）
1. **M2 网关机器学习模型**：基于历史数据训练风险评分模型，替代规则匹配
2. **跨模型知识迁移**：论文发现 9B 模型用 27B 模型进化的 skill 更好，可探索
3. **安全联系人配置**：配置安全邮箱、PGP 密钥、漏洞响应团队
