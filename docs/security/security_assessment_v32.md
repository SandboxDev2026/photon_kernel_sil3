### 1.1 优化目标

### 1.2 apply_pending() 拆分详情

**优化前**: 67行，包含4个逻辑阶段（优先级过滤排序/逐个应用/统计/清理）

**优化后**: 主函数25行 + 4个职责单一的子函数：

| 子函数 | 职责 |
|--------|------|
| `_filter_and_sort_updates()` | 按优先级过滤和排序待处理更新 |
| `_apply_filtered_updates()` | 逐个应用过滤后的更新，返回统计结果 |
| `_apply_single_update()` | 应用单个配置更新（非dry-run模式，写入配置文件） |
| `_cleanup_applied_updates()` | 清理已应用或失败的更新，保留pending状态的 |

### 1.3 功能验证

| 测试场景 | 结果 |
|---------|------|
| 添加2个待处理更新 | ✅ pending_updates=2 |
| 应用全部更新（dry-run） | ✅ applied=2, failed=0 |
| 清理已应用更新 | ✅ 剩余pending=0 |
| 按优先级过滤（high及以上） | ✅ 只应用high优先级 |

### 1.4 优化后函数长度检查
