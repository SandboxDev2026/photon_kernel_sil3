## 一、新增产品化模块说明

### 1.1 PlaybookEngine 自动化剧本编排（527行）

**文件**: `ops/playbook_engine.py`

将合规引擎与熔断机制产品化：当触发法案合规违规或安全威胁时，支持通过编排剧本进行自动处置。

**核心能力**:
- 7种触发器类型（合规违规/安全威胁/指标阈值/逃逸尝试/资源耗尽/审计失败/手动）
- 13种动作类型（隔离容器/冻结账号/撤销权限/关闭沙盒/发送告警/弹窗提醒/扩容/缩容/创建工单/快照证据/回滚/通知管理员）
- 人工审批机制（高危动作需要审批）
- 失败回滚机制
- 完整审计日志
- 支持JSON文件加载剧本定义

**安全设计**:
- 剧本可声明式定义，支持条件触发+动作序列
- 动作可插拔，生产环境替换为真实操作
- 执行可审计，每次剧本执行记录完整审计日志
- 高危动作需要人工审批，防止误操作

### 1.2 TicketSystem 工单与通报流转系统（530行）

**文件**: `ops/ticket_system.py`

提供工单流转接口，将沙盒捕获的底层异常自动转化为运维工单，形成"发现-告警-处置-复盘"完整闭环。

**核心能力**:
- 7种工单状态（创建/分诊/处理中/已解决/已关闭/已升级/已重开）
- 4种优先级（P1紧急/P2高/P3中/P4低）
- 9种类别（安全威胁/合规违规/逃逸尝试/资源耗尽/系统错误/性能下降/审计失败/网络问题/其他）
- SLA管理（响应时间/解决时间/超时升级）
- 通报通知（邮件/短信/IM/Webhook）
- 复盘记录（根因分析/改进措施/预防措施）
- 统计报表（按状态/优先级/类别/处理人统计）
- JSON导出

**安全设计**:
- 从事件自动创建工单，风险等级自动映射优先级
- SLA超时自动升级
- 复盘记录关联工单，形成完整闭环
- 工单评论支持内部/外部区分

### 1.3 InferenceMetrics 推理指标监控（430行）

**文件**: `ops/inference_metrics.py`

除了基础的资源水位，重点监控推理相关的指标。

**核心指标**:
- QPS（每秒查询数）
- 首Token延迟（TTFT, Time To First Token）
- Token生成速度（Tokens/sec）
- 显存碎片率（控制在15%以下）
- 请求队列深度
- 错误率
- P50/P95/P99延迟
- GPU利用率（目标70-85%）
- VRAM使用量/总量

**核心能力**:
- 滑动窗口统计（最近1/5/15分钟）
- Prometheus格式导出
- 告警阈值检查（P99>500ms/错误率>1%/显存碎片>15%）
- 线程安全（多线程环境下可安全使用）
- 累计计数器

### 1.4 MonitorDashboard 可视化监控大屏（377行）

**文件**: `ops/monitor_dashboard.py`

参考业界安全感知平台，开发专属的监控大屏。

**核心能力**:
- 深色主题（运维大屏标准）
- 核心指标卡片展示
- 实时告警面板（当前告警列表+历史告警）
- 集群拓扑（节点/沙盒实例/网络流量）
- 告警阈值配置展示
- 健康状态指示（健康/警告/严重）
- 自动刷新（5秒）
- JSON格式API输出

**严格告警阈值**:
- P99延迟 > 500ms → 严重告警
- 错误率 > 1% → 严重告警
- 显存碎片率 > 15% → 警告
- GPU利用率 > 85% → 扩容建议
- GPU利用率 < 70% → 缩容建议
- 队列深度 > 100 → 警告

### 1.5 HPA 弹性伸缩配置（130行）

**文件**: `deploy/hpa.yaml`

结合Kubernetes的HPA（水平Pod自动扩缩容）机制。

**核心配置**:
- 基于CPU利用率（70%）
- 基于内存利用率（80%）
- 基于自定义指标QPS（每Pod 100）
- 基于自定义指标GPU利用率（目标75%，70-85%区间）
- 基于请求队列深度（50）
- 扩容稳定窗口60秒，缩容稳定窗口300秒
- 扩容策略：最大50%或5个Pod（取大）
- 缩容策略：最大25%或2个Pod（取小）
- StrongPool专用HPA（MicroVM启动慢，扩容窗口120秒）

### 1.6 高可用架构配置（300行）

**文件**: `deploy/high-availability.yaml`

设计至少双实例 + 负载均衡的高可用架构，支持模型的蓝绿部署与热切换。

**核心配置**:
- LoadBalancer Service（跨可用区负载均衡）
- Blue部署（3实例，滚动更新零中断）
- Green部署（0实例，蓝绿切换时扩容）
- Pod反亲和（分散到不同节点）
- 拓扑分布约束（跨可用区分布）
- PodDisruptionBudget（至少2个Pod可用）
- NetworkPolicy（限制入站/出站流量）
- 蓝绿切换Service（blue/green独立Service）
- 存活探针/就绪探针/启动探针
- 优雅终止（60秒）
- GPU资源请求/限制

## 七、剩余风险与建议

### 高优先级建议（P1）
1. **升级依赖版本**：OpenSSL >=3.0.7、grpcio >=1.62.0、Firecracker >=1.5.0
2. **Playbook动作生产化**：当前13种动作为模拟实现，生产环境需替换为真实K8s API/云API调用
3. **Ticket通知集成**：当前通知为回调接口，生产环境需集成邮件/短信/IM/Webhook
4. **Dashboard实时数据**：当前大屏为静态渲染，生产环境需接入WebSocket/Server-Sent Events实时推送

### 中优先级建议（P2）
1. **new/delete改智能指针**：6处裸new/delete建议改用std::unique_ptr
2. **popen改fork+execv**：65处popen长期建议改用fork+execv
3. **InferenceMetrics接入真实GPU**：当前GPU指标为手动更新，生产环境需接入nvidia-smi/NVML
4. **HPA自定义指标**：需要部署Prometheus Adapter才能使用自定义QPS/GPU指标

### 低优先级建议（P3）
1. **第三方安全审计**：公网多租户场景建议独立第三方渗透测试
2. **蓝绿部署自动化**：当前蓝绿切换为手动，建议集成Argo CD/Flux自动化
3. **多活部署**：当前为单集群高可用，跨区域多活需要额外配置
