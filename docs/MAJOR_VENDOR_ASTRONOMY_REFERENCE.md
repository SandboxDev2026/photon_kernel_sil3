# 大厂开源宇宙/天文沙盒项目参考

**日期**: 2026-09-04
**状态**: 技术调研参考
**说明**: 大厂没有直接开源完整成品宇宙沙盒游戏，但开放了天文可视化、轨道仿真、星图渲染、真实数据处理的底层库与 Demo，全部可摘抄工程思路、数据接入、渲染管线。

## 一、NASA（美国国家航空航天局）

### 1.1 Open-NASA-WorldWind

| 项目 | 详情 |
|------|------|
| 仓库 | NASA-WorldWind |
| 协议 | Apache-2.0 |
| 技术栈 | Java / WebGL / C# |

**可抄部分**:
- **行星球体瓦片 LOD 渲染**：地球、火星、月球地形真实高程数据接入
- **坐标系转换**：J2000 天球坐标、惯性系/地固系变换（做宇宙沙盒核心）
- **相机漫游**：超大尺度空间导航逻辑
- **SPICE 内核解析工具**：卫星、行星轨道计算

**适合**: 真实天体坐标系统、大规模天体瓦片渲染

**借鉴到 PhotonBox**:
- 瓦片 LOD 思想 → 沙盒实例分级管理（活跃/休眠/归档不同粒度）
- 坐标系转换 → 多命名空间网络坐标映射
- 相机漫游 → 沙盒集群资源全景导航

---

### 1.2 SPICE Toolkit（NASA 核心轨道库）

| 项目 | 详情 |
|------|------|
| 仓库 | NASA SPICE |
| 协议 | NASA 开源许可，可商用 |
| 技术栈 | C/Fortran，第三方 C++/JS 绑定 |

**可抄**:
- 太阳系所有行星、卫星、探测器高精度轨道、姿态计算

**重要提示**: Pioneer、OpenSpace 内部就是封装 SPICE。不要自己手写开普勒轨道，直接抄它的坐标变换逻辑。

**避坑**: SPICE 原始是 Fortran，不要直接硬抄 Fortran；找 C 语言包装层，只抄算法逻辑。

**借鉴到 PhotonBox**:
- 高精度轨道计算 → 沙盒资源使用趋势精确预测
- 姿态计算 → 沙盒实例状态机精确转换

## 二、谷歌 Google

### 2.1 Google Sky Map（星图）

| 项目 | 详情 |
|------|------|
| 仓库 | google/skymap |
| 协议 | Apache-2.0 |
| 技术栈 | Android + OpenGL |

**可抄**:
- **依巴谷、第谷星表加载解析**：恒星亮度、颜色渲染
- **设备姿态与天球映射**：星点剔除、分级 LOD 星点渲染

**注意**: 虽然是移动端 App，星表解析、星点渲染逻辑可以剥离出来移植到 C++/WebGL。

**借鉴到 PhotonBox**:
- 星表解析 → 安全事件日志批量解析
- 分级 LOD 星点渲染 → 安全事件分级处理（critical/high/medium/low 不同粒度）
- 星点剔除 → 审计日志噪声过滤

Google 公开天文可视化 demo，无完整产品，但开源 WebGL 天文渲染示例。

## 三、微软 Microsoft

### WorldWide Telescope（WWT 世界望远镜）

| 项目 | 详情 |
|------|------|
| 仓库 | WorldWideTelescope |
| 协议 | MIT（非常友好） |
| 技术栈 | TypeScript/WebGL，C# 后端 |
| 背景 | 微软交给社区维护，原始是微软研究院项目 |

**可抄重点**:

1. **多源天文数据集统一抽象层**：FITS 天文图像、星表、星云图像加载
2. **宇宙层级浏览**：太阳系→银河系→深空，相机平滑穿越超大尺度空间
3. **数据格式适配器**：把多种天文观测数据归一化为内部场景对象
4. **Web 端高性能海量星点渲染**

**工业级架构，MIT 协议，几乎没有传染性，适合自研沙盒直接借鉴架构。**

**避坑**: WWT 是 WebGL，如果你写 C++ 沙盒，抄它的对象模型和数据流，不要直接复制 GLSL。

**借鉴到 PhotonBox**（重点参考）:
- **多源数据统一抽象层** → PhotonBox 多源审计日志统一抽象层（seccomp/eBPF/gRPC/文件日志/HMAC 链统一接口）
- **宇宙层级浏览** → 沙盒集群层级导航（节点→池→实例→进程）
- **数据格式适配器** → 不同格式审计日志归一化为内部 SecurityEvent 对象
- **超大尺度相机漫游** → 监控大屏从全局集群视图钻取到单个沙盒实例

## 四、国内大厂开源相关

### 4.1 华为 openEuler 灵衢（LingQu）

| 项目 | 详情 |
|------|------|
| 仓库 | openEuler/lingqu |
| 协议 | Mulan-2.0 |
| 技术栈 | C++ |
| 定位 | 不是宇宙沙盒，是分布式仿真沙盒框架，适合做多节点仿真推演 |

**可抄**:
- **仿真调度框架**：任务分片、时间步进引擎
- **插件化沙盒调度**：隔离执行、事件驱动仿真引擎
- 如果你想做多实例分布式宇宙仿真（多沙盒并行跑 N 体），调度层可以抄灵衢，天体渲染部分需要自己接 WWT/NASA 的数据层。

**借鉴到 PhotonBox**（重点参考）:
- **分布式仿真调度** → PhotonBox 分布式沙盒集群调度
- **事件驱动仿真引擎** → PhotonBox 安全事件驱动的防御规则引擎
- **插件化沙盒调度** → PhotonBox 沙盒后端插件化（LightPool/StrongPool/gVisor/Wasm 可插拔）

## 九、关键现实点

1. **大厂不会开源完整"可以直接玩的宇宙沙盒成品"**，成本太高；开放的是数据处理、坐标系、渲染底座、仿真调度。
2. **不要自己手写开普勒轨道**，直接封装 NASA SPICE，Pioneer 和 OpenSpace 都是这么做的。
3. **SPICE 原始是 Fortran**，找 C 语言包装层，只抄算法逻辑，不要硬抄 Fortran。
4. **WWT 是 WebGL**，写 C++ 沙盒时抄它的对象模型和数据流，不要直接复制 GLSL。
5. **华为灵衢没有天体物理渲染**，只借鉴调度层，渲染部分接 WWT/NASA 数据层。
